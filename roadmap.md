# ТЗ и роадмап: AI-студия контента с цифровым аватаром
### (по мотивам разбора vavs.ai)

---

## 1. Продукт одной фразой

SaaS, где пользователь один раз собирает AI-персонажа (внешность + голос + характер + ниша), а дальше платформа сама генерирует видео с говорящей головой, фото, карусели и текстовые посты под этого персонажа — и раскладывает всё в календарь публикаций. Монетизация: подписка (тариф = лимит токенов и персонажей) + докупка токенов пакетами.

Целевой пользователь: соло-предприниматели, инфобизнес, эксперты и малый бизнес, которым нужен постоянный поток контента для соцсетей без съёмок, оператора и монтажёра.

## 2. Функциональная карта

### 2.1 Конструктор персонажа (7 шагов)

| Шаг | Что настраивается | Комментарий по реализации |
|---|---|---|
| 1. Физика | язык, пол, возраст (слайдер), этнос | язык персонажа фиксируется навсегда — влияет на промпты генерации |
| 2. Внешность | комплекция, цвет/длина волос, глаза, нос, губы, растительность, стиль одежды | у каждого варианта — превью реального лица; либо заранее отрендеренная матрица комбинаций, либо генерация превью на лету через image-модель |
| 3. Голос | библиотека готовых голосов (с описанием характера/возраста) ИЛИ "свой голос" по текстовому описанию | готовые голоса — заранее сгенерированные сэмплы TTS; кастомный голос — TTS-провайдер с возможностью synthesis "by prompt" |
| 4. История | 6 шаблонов предыстории (self-made, трудное детство, духовный путь и т.д.) | это просто затравки для LLM-промпта, не отдельная генерация |
| 5. Душа | архетип (12 архетипов Юнга) + слайдер темперамента | тоже вход в промпт LLM, определяет тон сценариев |
| 6. Ниша | 11 категорий + под-специализации, раскрывающиеся после выбора родительской категории + своя ниша текстом | влияет на тематику авто-генерируемых идей контента |
| 7. Генерация | сводка параметров, доп. описание (до 1000 симв., с голосовым вводом), явное согласие на обработку биометрии (фото/голос), запуск | ИИ генерирует: (а) текстовое "досье" персонажа — характер, ценности, манера речи, (б) 3 фото на выбор |

Отдельная ветка — **"Цифровой образ"**: пользователь загружает 3 своих фото + голос → получает цифрового двойника себя (used для личного бренда, не выдуманного персонажа).

### 2.2 Студия контента

**Видео (6 шагов)** — самый тяжёлый пайплайн:
Настройки (аватар, тип ролика — говорящая голова / динамичный с B-roll / закадровый / реклама, длительность 30-60с, язык, стиль B-roll, субтитры, музыка) → Идея → Сценарий → Сториборд → Кадры → Предпросмотр.
Стоимость: от 52 токенов.

**Фото (3 шага):** Бриф (формат под площадку, стиль — Кино/UGC/Pixar/Глянец, аватар опционально, фон/локация текстом или референс-фото, одежда референс-фото, идея кадра, крупность плана) → Кадры → Готово.
Стоимость: от 1 токена.

**Карусель (3 шага):** Бриф (тема одной фразой, формат 4:5/1:1, число слайдов 3-10, формат подачи — вирусный/экспертный/продающий/личный, готовый визуальный стиль-шаблон) → Слайды → Готово.
Стоимость: 1 токен/слайд, правки текста бесплатны.

**Текст (2 шага):** Бриф (тема, длина под конкретную площадку — Threads/Instagram/TikTok/LinkedIn/YouTube/Telegram/VK/Дзен, стиль написания, опционально картинка с теми же настройками, что и в "Фото") → Готово.
Стоимость: от 1 токена, перегенерация абзацев бесплатна.

### 2.3 Планер и управление

- Календарь публикаций с фильтром по типу контента + "Автопланирование" (вероятно: LLM сам предлагает контент-план на месяц исходя из ниши персонажа).
- "Мой контент" — архив сгенерированного.
- Реферальная программа, гайд для новичков, сообщество в Telegram как канал поддержки/онбординга.

## 3. Техническая архитектура

### 3.1 Вероятный стек "оригинала" (по паттернам UX)

- **LLM** (GPT-4o / Claude / Gemini) — генерация досье персонажа, сценариев, идей, текстов постов, структуры каруселей.
- **Голос — вероятно ElevenLabs**: библиотека голосов с характерными описаниями + клонирование по тексту/образцу — это узнаваемый паттерн их API.
- **Говорящий аватар по фото+голосу** — сценарий "3 фото + голос → цифровой двойник" почти точно повторяет продукты HeyGen (Photo/Instant Avatar), Akool Talking Photo или D-ID. С нуля такую модель никто не обучает — это оборачивание готового B2B API.
- **Фото/B-roll** — диффузионная модель с поддержкой референсов лица и одежды (Flux + IP-Adapter/LoRA, либо Midjourney/Kling через API).
- **Сборка видео** — программный монтаж (ffmpeg или Remotion): субтитры, музыка, переходы поверх сгенерированных клипов.
- **Оркестрация** — очередь асинхронных задач (генерация явно многошаговая и небыстрая).

### 3.2 Рекомендуемый стек для своей реализации

| Слой | Технология |
|---|---|
| Backend | Node.js (NestJS) или Python (FastAPI) |
| Очереди/джобы | BullMQ (Redis) или Celery — обязательны, генерации асинхронные и долгие |
| БД | PostgreSQL |
| LLM | любой топовый через API — сценарии, досье, тексты |
| TTS/клонирование голоса | ElevenLabs API |
| Говорящее видео | HeyGen API или Akool API (не разрабатывать lip-sync самостоятельно) |
| Фото/B-roll | Flux (через Replicate/Fal.ai) с референсом лица для консистентности персонажа |
| Видео-монтаж | Remotion (React → видео, удобно для программной сборки с субтитрами) |
| Хранилище файлов | S3-совместимое (Cloudflare R2 / Yandex Object Storage) |
| Оплата (RU) | ЮKassa / CloudPayments + таблица токен-транзакций |
| Фронт | Next.js — пошаговые wizard-формы, как в оригинале |

### 3.3 Модель данных (укрупнённо)

```
users            (id, email, tokens_balance, subscription_id, ...)
subscriptions    (id, user_id, plan, status, renews_at)
characters       (id, user_id, physique, appearance, voice_id, backstory,
                  archetype, temperament, niche, bio_text, photo_urls[], language)
content_items    (id, user_id, character_id, type[video|photo|carousel|post],
                  status, brief_json, result_urls[], tokens_spent, created_at)
generation_steps (id, content_item_id, step_name, status, provider, cost_usd,
                  input_json, output_json)  -- лог каждого вызова внешнего API
token_ledger     (id, user_id, delta, reason, content_item_id, created_at)
schedule_posts   (id, content_item_id, planned_at, platform, status)
```

Важно: списывать токены **по факту успешного завершения генерации**, а не в момент запроса — иначе неудачные генерации будут "съедать" баланс пользователя.

**Оценка себестоимости 30-секундного видео** (говорящая голова + короткая озвучка):
- Аватар-видео: 0.5 мин × $3–4 ≈ **$1.5–2.0**
- Озвучка (≈500 симв.): ≈ **$0.10**
- 1-2 B-roll кадра (Flux Dev): ≈ **$0.02–0.05**
- LLM (сценарий): ≈ **$0.01–0.03**
- **Итого ≈ $1.6–2.2** (≈ 150–200 ₽ по курсу ~90 ₽/$)

При этом на тарифе Entry эффективная цена 30-сек видео для клиента ≈ 3 980 ₽ / 4 видео ≈ **995 ₽**. Валовая маржа по инфраструктуре — **≈ 80%**, что типично и здорово для обёртки над чужими AI-API (основные затраты бизнеса тогда — не инфраструктура, а привлечение клиентов и удержание).

**Себестоимость фото** (Flux Pro, 1 генерация): ≈ $0.05 (≈ 4,5 ₽) против цены в 1 токен (по Entry-тарифу ≈ 16,6 ₽) — маржа ещё выше.

**Оговорка:** курсы валют, цены провайдеров и реальный стек оригинала могут отличаться — приведённые цифры ориентировочные, для планирования модели, а не гарантированный факт о том, что использует vavs.ai.

## 5. Дорожная карта

**Фаза 0 — Фундамент (2-3 недели)**
Auth, биллинг, токен-леджер, базовая БД, лендинг с тарифами.

**Фаза 1 — MVP: персонаж + один формат (4-6 недель)**
Урезанный конструктор персонажа (внешность/голос/ниша, без всех 7 шагов) + генерация **фото** (дешевле и технически проще видео) + текстовых постов. Цель — проверить unit-экономику и удержание на живых пользователях, не вкладываясь сразу в дорогой видео-пайплайн.

**Фаза 2 — Карусели (2-3 недели)**
LLM пишет структуру → рендер слайдов (HTML→PNG через Puppeteer/Satori или Canvas-шаблоны).

**Фаза 3 — Видео (6-8 недель, самая дорогая часть)**
Сначала просто говорящая голова без B-roll и сториборда → затем полный пайплайн идея→сценарий→сториборд→кадры→сборка.

**Фаза 4 — Планер, автопланирование, реферальная программа**
Полировка удержания и виральности.

## 6. Юридические и комплаенс-моменты

- Экраны согласия на обработку биометрических данных (фото лица, голос) в оригинале — не декоративные. В РФ биометрия — персональные данные специальной категории (152-ФЗ), обработка требует явного отдельного согласия и постановки на учёт как оператора биометрических данных. Это стоит реализовать **в первую очередь**, а не как доработку "потом".
- Нужны отдельные условия использования именно для AI-аватаров (что явно есть у vavs.ai — ссылка "Условия использования AI-аватаров" на шаге генерации), плюс подтверждение, что загружаемое лицо — либо самого пользователя, либо с явного согласия человека.
- Если будет клонирование голоса реальных людей — аналогичная история с согласием.

## 7. Открытые вопросы для дальнейшей проработки

1. Какой провайдер аватар-видео даёт лучшее качество лица/липсинка на русском языке при приемлемой цене (HeyGen vs Akool vs D-ID vs Hedra) — нужен practical benchmark на реальных роликах.
2. Нужна ли консистентность лица персонажа между фото/каруселью/видео (LoRA на персонажа) или каждый формат генерируется независимо.
3. Как реализовано "Автопланирование" — вероятно LLM генерирует контент-план по нише, но нужно решить, генерирует ли оно сразу контент или только темы.
4. Стоит ли на старте вообще копировать бренд/дизайн 1:1 или лучше дифференцироваться визуально и по нишевому фокусу (например, специализация на фитнес-нише, где у тебя уже есть экспертиза и клиенты через Champion Fitness).
